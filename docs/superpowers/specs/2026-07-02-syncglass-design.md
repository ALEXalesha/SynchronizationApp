# SyncGlass — дизайн приложения синхронизации папок

Дата: 2026-07-02

## Цель

Настольное приложение для Windows, которое сравнивает файлы в двух папках
(локальная на ноутбуке и сетевая на другом компьютере) и синхронизирует их —
приводит папку-приёмник к точной копии папки-источника: копирует новые файлы,
удаляет лишние, перезаписывает изменённые. Дизайн — «liquid glass» в стиле Apple.

## Ключевые решения

| Вопрос | Решение |
|---|---|
| Доступ к сетевой папке | Обычный путь файловой системы: UNC (`\\Комп\Папка`) или подключённый диск (`Z:\`) |
| Направление | Обе стороны, выбор переключателем перед синхронизацией |
| Технология | Electron (HTML/CSS/JS + Node.js `fs`) |
| Удаление лишних файлов | В Корзину Windows через `shell.trashItem` |
| Гранулярность выбора | Чекбоксы по папкам верхнего уровня; внутри синхронизация рекурсивная |

## Архитектура

Electron, два процесса:

- **Main (Node.js)** — вся работа с файлами: сканирование, сравнение, копирование,
  удаление в корзину. Общается с renderer через IPC.
- **Renderer** — интерфейс liquid glass. Ничего не знает о файловой системе напрямую,
  только шлёт запросы в main и рисует результат/прогресс.
- **Preload** — безопасный мост `contextBridge`, пробрасывает узкий набор IPC-вызовов.

### Модули

- `src/sync.js` — **чистая логика планирования** (без файловых операций). На вход два
  списка записей (имя, размер, mtime), на выход план: что копировать, удалять,
  перезаписывать. Легко тестируется юнит-тестами.
- `src/fsops.js` — файловые операции: рекурсивный скан папки в список записей,
  выполнение плана (копирование/трэш) с колбэком прогресса.
- `main.js` — Electron main, IPC-обработчики, диалоги выбора папок.
- `preload.js` — мост IPC.
- `renderer/` — `index.html`, `styles.css`, `renderer.js`.

## Интерфейс (сверху вниз)

1. **Верхняя панель**: заголовок, стеклянный тумблер направления
   (Локально → Сеть / Сеть → Локально), кнопка «Обновить».
2. **Две стеклянные панели**: слева локальные папки, справа сетевые.
   Строка папки: чекбокс, имя, число файлов, размер. Различия подсвечены.
3. **Кнопка «Выбрать все»** + счётчик выбранного.
4. **Нижняя панель**: поля путей (Локальная / Сетевая) + кнопки «Обзор…».
5. **Кнопка «Синхронизировать»**.

## Логика синхронизации

- Сравнение файлов по **относительному пути + размер + mtime**.
- Источник/приёмник задаёт переключатель направления.
- Для каждой выбранной папки верхнего уровня — рекурсивный обход:
  - файл есть в источнике, нет в приёмнике → **копировать**;
  - файл есть в обоих, но размер/mtime отличаются → **перезаписать**;
  - файл есть в приёмнике, нет в источнике → **в Корзину**.
- Пустые лишние папки на приёмнике удаляются, недостающие создаются.

## Безопасность

Удаление необратимо для пользователя, поэтому:

- Перед выполнением — **окно предпросмотра**: «скопировать N, удалить M, перезаписать K»
  с раскрываемым списком. Выполнение только после явного подтверждения.
- Удаление идёт в Корзину, а не мимо неё.

## Тестирование

- `src/sync.js` покрывается юнит-тестами: разные комбинации списков →
  проверка корректности плана (копирование/удаление/перезапись/без изменений).
- `src/fsops.js` — интеграционные тесты на временных папках: создать структуру →
  выполнить план → проверить результат.

## Вне рамок (YAGNI)

- Нет облака/сервера/сетевых протоколов — только пути файловой системы.
- Нет частичного выбора вложенных файлов — выбор по папкам верхнего уровня.
- Нет фонового автосинка по расписанию — синхронизация по кнопке.
